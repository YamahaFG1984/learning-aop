CHAPTER 02

初识 AspectJ

一句话概括本章：写出你的第一个切面，认识 join point / pointcut / advice / aspect 这四个词，并搞懂“织入”到底发生在什么时候。

本章你将学到

  • 用两种语法写同一个切面：传统 .aj 语法，和更现代的 @AspectJ 注解语法
  • 编译期织入 / 二进制织入 / 加载期织入（LTW）三种方式的直觉区别
  • 织入之后的类“变成了什么样子”（源码层面模拟一下织入结果）
  • Spring 怎么在不用 AspectJ 编译器的情况下，也能跑 @AspectJ 语法的切面

1. 一个朴素的业务类

书中示例仓库 ch02/workspace/Section2.1.2AddingAnAspect 里有一个非常简单的 MessageCommunicator：它只会把消息打印出来，完全不知道“权限校验”这回事。

ajia/messaging/MessageCommunicator.java
package ajia.messaging;

public class MessageCommunicator {
    public void deliver(String message) {
        System.out.println(message);
    }
    public void deliver(String person, String message) {
        System.out.println(person + ", " + message);
    }
}

现在的需求是：调用 deliver 之前必须先做一次身份认证。传统写法要在每个方法里手写一行 authenticator.authenticate()——这就是第 1 章说的“纠缠”。AOP 的做法是：一行都不改 MessageCommunicator，另外写一个切面。

2. 传统语法：.aj 文件

这是仓库里真实的 SecurityAspect.aj（为可读性略去了版权头）：

ajia/security/SecurityAspect.aj
package ajia.security;

import ajia.messaging.MessageCommunicator;

public aspect SecurityAspect {
    private Authenticator authenticator = new Authenticator();

    pointcut secureAccess()
        : execution(* MessageCommunicator.deliver(..));

    before() : secureAccess() {
        System.out.println("Checking and authenticating user");
        authenticator.authenticate();
    }
}

逐行对应回上一章的四个词：

代码对应概念
public aspect SecurityAspect { ... }切面：新的模块单元，语法上很像 class
execution(* MessageCommunicator.deliver(..))切点表达式：选中“MessageCommunicator 类里任意返回值、任意参数的 deliver 方法被执行”这件事；* 通配返回值，.. 通配参数列表
pointcut secureAccess() : ...给上面这条切点表达式起个名字，方便复用
before() : secureAccess() { ... }通知：在命中的连接点（也就是每次 deliver 方法真正被调用时）之前执行这段代码
图 2-1　连接点是“候选事件”，切点从中筛选，通知定义命中后做什么，三者一起装在一个切面里

3. 更现代的写法：@AspectJ 注解语法

从 AspectJ 5 开始（AspectWerkz 并入之后），同一个切面可以完全用普通 Java 注解写出来，不需要 .aj 文件，也不强制要求专用编译器：

ajia/security/SecurityAspect.java（@AspectJ 语法版本）
package ajia.security;

import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.Before;
import org.aspectj.lang.annotation.Pointcut;

@Aspect
public class SecurityAspect {

    private Authenticator authenticator = new Authenticator();

    @Pointcut("execution(* ajia.messaging.MessageCommunicator.deliver(..))")
    public void secureAccess() {}

    @Before("secureAccess()")
    public void secure() {
        System.out.println("Checking and authenticating user");
        authenticator.authenticate();
    }
}
.aj 传统语法
  • 需要 ajc 专用编译器（或至少专用插件）
  • 语法更简洁，能表达全部 AspectJ 特性（含第 5 章的类型间声明）
  • 普通 Java IDE/工具默认不认识 .aj
@AspectJ 注解语法（新代码推荐）
  • 本质是合法的 Java 代码，javac 能编译（但要真正生效仍需织入器或 Spring AOP 代理）
  • IDE 补全、重构、静态检查全部可用
  • 是 Spring AOP 唯一支持的书写方式，见第 9 章

注意一个容易踩的坑，书里也特别提醒过：单用 javac 编译带 @Aspect 的类，程序照样能跑，但切面完全不会生效——因为 javac 根本不认识 @Aspect 的语义，你还需要一个织入器或者 Spring 的代理机制真正把逻辑接上。

4. 织入到底发生在什么时候

AspectJ 提供三种织入时机，效果完全等价，只是发生的阶段不同：

图 2-2　三条路径殊途同归：不管在哪个阶段织入，最终 JVM 拿到的都是“切面逻辑已经焊进去”的字节码

本章只需要有这个直觉；第 8 章会展开讲三种方式各自的取舍（比如 LTW 不用改构建脚本，但需要 -javaagent 启动参数）。

💡 一个更容易记住的类比

把 ajc 想象成 C/C++ 的链接器（linker）：javac/普通编译产出的 .class 相当于「目标文件」，织入器把「目标文件」和「切面」链接在一起，产出最终可执行的「字节码」。源码织入只是把「编译」和「链接」这两步合并成了一步。

5. 现代化改造：用 Maven 而不是 Ant 跑起来

书中 2009 年版本用的是 ajc 命令行 + Ant（仓库里 run-ant.sh）或很旧版本的 Maven 插件。 今天写新项目，建议直接用 Maven（或 Gradle）+ 社区维护的 AspectJ 编译插件：

书中写法（已过时）
  • AspectJ 1.6.x，手动下载安装到 ASPECTJ_HOME
  • Ant + iajc 任务，或非常旧的 Maven aspectj-maven-plugin
  • 命令行手敲 ajc -source 5 ...
推荐的现代写法
  • AspectJ 1.9.x，作为 Maven 依赖引入，无需单独安装
  • Maven：dev.aspectj:aspectj-maven-plugin（老牌的 org.codehaus.mojo:aspectj-maven-plugin 已多年未更新，这是社区活跃维护的替代品）
  • Gradle：io.freefair.aspectj 插件
pom.xml（关键片段，目标 Java 17）
<properties>
  <aspectj.version>1.9.22.1</aspectj.version>
</properties>

<dependencies>
  <dependency>
    <groupId>org.aspectj</groupId>
    <artifactId>aspectjrt</artifactId>
    <version>${aspectj.version}</version>
  </dependency>
</dependencies>

<build>
  <plugins>
    <plugin>
      <groupId>dev.aspectj</groupId>
      <artifactId>aspectj-maven-plugin</artifactId>
      <version>1.14</version>
      <configuration>
        <source>17</source>
        <target>17</target>
        <complianceLevel>17</complianceLevel>
        <aspectLibraries>
          <!-- 依赖里的切面库，例如 spring-aspects -->
        </aspectLibraries>
      </configuration>
      <executions>
        <execution>
          <goals>
            <goal>compile</goal>
            <goal>test-compile</goal>
          </goals>
        </execution>
      </executions>
    </plugin>
  </plugins>
</build>
⚠️ 版本号仅供参考

AspectJ 和 dev.aspectj:aspectj-maven-plugin 都在持续发布新版本，实际项目里请到 Maven Central 查询当时的最新版本号，不要把本笔记里的版本号当成“永远最新”。

6. 一个预告：Spring 不需要 ajc 也能跑 @AspectJ 语法

如果你的 SecurityAspect 是用 @AspectJ 注解写的，Spring 容器可以直接识别它， 在 @Configuration 类上加一行 @EnableAspectJAutoProxy（对应书中 XML 时代的 <aop:aspectj-autoproxy/>），Spring 就会给 MessageCommunicator 这个 Bean 自动生成一个代理对象，在方法调用前后插入切面逻辑——全程不需要 AspectJ 编译器，也不需要 -javaagent。 代价是：它只能拦截“方法执行”这一种连接点，而且只对 Spring 容器管理的 Bean 生效。这是第 9 章的主角，这里先有个印象即可。

✏️ 动手练习

打开仓库里的 ch02/workspace/Section2.1.2AddingAnAspect，把 pom.xml 换成本节的现代化片段，用 mvn compile exec:java -Dexec.mainClass=ajia.main.Main 跑一遍， 观察控制台是否先打印出“Checking and authenticating user”再打印消息内容。 然后再看看 ch02/workspace/Section2.2.3InterTypeDeclaration 里的 TrackingAspect.aj—— 它演示了第 5 章才会详细讲的“类型间声明”，可以先睹为快。

小结 & 自测

  • execution(* MessageCommunicator.deliver(..)) 里两个 */.. 分别是什么意思？
    * 通配返回值类型（任意类型都行）；.. 通配参数列表（任意数量、任意类型的参数）。
  • 为什么单用 javac 编译 @AspectJ 语法的类，切面不会生效？
    javac 只认识极少数标准注解（如 @Override），不理解 @Aspect/@Before 的语义。必须再经过一个织入器（ajc）或者依赖 Spring AOP 的代理机制，才能让切面逻辑真正接入执行路径。
  • 源码织入、二进制织入、加载期织入，最终产出的运行结果一样吗？
    一样。三者只是“在哪个阶段把切面焊进字节码”不同，焊接完成后 JVM 执行的字节码在语义上是等价的。
  • 新项目应该优先选 .aj 语法还是 @AspectJ 语法？
    没有静态类型间声明等高级需求时，优先 @AspectJ 注解语法：IDE 支持更好、和 Spring 天然兼容、团队上手成本更低。.aj 语法在需要第 5 章的类型间声明等能力时仍然有用。
  • 书中的 org.codehaus.mojo:aspectj-maven-plugin 现在还推荐用吗？
    不推荐作为首选。它已多年缺乏更新，社区维护的 dev.aspectj:aspectj-maven-plugin 是目前更活跃的替代品，具体版本以 Maven Central 为准。
