第 9 章

与 Spring 集成

一句话概括本章：Spring 自带一套"轻量版 AOP"——本质是给 Bean 套一层代理；理解它的能力边界，才知道什么时候该换成真正的 AspectJ 织入。

本章你将学到

  • Spring AOP 的底层原理：JDK 动态代理 与 CGLIB/ByteBuddy 代理
  • 为什么"自己调自己"的方法不会被增强（经典的自调用陷阱）
  • 用 @Aspect 注解在 Spring 里写切面（不用配 XML）
  • 什么时候 Spring AOP 不够用，需要请出完整版 AspectJ

1. Spring AOP 是什么：一个"代理生成器"

前几章讲的 AspectJ 是"编译器级别"的 AOP：它直接把切面代码焊进 .class 字节码里， 所以理论上能拦截任何连接点——方法调用、字段访问、对象创建……几乎无所不能。

但 Spring 不想强迫所有用户都去搞编译期/类加载期织入这么"重"的东西。于是 Spring 发明了自己的一套 AOP 实现—— Spring AOP。它的原理简单粗暴：不改字节码，而是在运行时给目标 Bean 套一层"代理壳"。

💡 类比

Spring AOP 就像给快递包裹套的"塑封膜"（代理）：只有快递员从外面拿快递时才会经过安检（advice）。 但如果收件人自己在仓库内部把东西从一个箱子挪到另一个箱子（Bean 内部自调用），根本不会经过大门的安检机—— 因为压根没有"拆包裹再装箱"这个外部动作。

这就是 Spring AOP 最典型的"坑"：只有通过代理对象发起的调用才会被增强。 如果 removeProduct() 内部直接调用了同一个类里的 isProductAvailable()， 这次调用是 this.isProductAvailable()，压根没有经过代理，切面自然不会生效。

书里给出的补救办法是用 AopContext.currentProxy() 拿到当前代理再调用——但这样业务代码就"知道"了自己被代理， 属于无奈之举，不推荐常态化使用。如果你经常需要拦截自调用，这就是该换用真正 AspectJ 织入的信号。

2. 两种代理：接口用 JDK 动态代理，类用字节码代理

目标 Bean 的形态Spring 使用的代理方式限制
实现了接口JDK java.lang.reflect.Proxy 动态代理代理对象只能声明为接口类型
没有实现接口的具体类运行时生成子类（历史上用 CGLIB，现代 Spring 内置了 Spring-repackaged ByteBuddy）无法代理 final 类 / final 方法
🔧 版本变化

书里讲的是独立的 cglib 第三方库。从 Spring Framework 6 / Spring Boot 3 开始， Spring 已经把动态子类代理换成了内部打包的 ByteBuddy（spring-core 自带， 类名类似 org.springframework.cglib... 只是历史包名保留），你不需要再手动引入 cglib 依赖， Spring Boot 会自动处理好一切。

为了直观理解"代理"到底是什么，可以先看一个不用 Spring、纯 JDK 的最小例子（对应仓库 ch09/workspace/Section9.2.1DynamicProxy）：

TracingInvocationHandler.java（JDK 动态代理，写法本身不过时）
public class TracingInvocationHandler implements InvocationHandler {
    private final Object target;

    public TracingInvocationHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("Entering " + method);
        return method.invoke(target, args); // 手动转发给真正的目标对象
    }
}

Spring AOP 做的事情本质上跟这段代码一样：invoke() 里先跑一遍你写的通知逻辑，再转发给真正的目标方法。 区别只是 Spring 把"生成代理 + 匹配切点 + 调用通知链"这一整套自动化了，你只需要声明切点。

3. 用 @Aspect 写 Spring 切面：告别 XML

对应仓库示例 ch09/workspace/Section9.1.2Utilizing@Aspect，一个库存操作审计（audit log）的切面：

InventoryAuditing.java（@AspectJ 注解语法，现在依然是主流写法）
@Aspect
public class InventoryAuditing {

    @Pointcut("execution(* *(ajia.domain.Product, int)) && args(product, quantity)")
    public void audited(Product product, int quantity) {}

    @Before("audited(product, quantity)")
    public void audit(JoinPoint jp, Product product, int quantity) {
        System.out.println("Audit: op=" + jp.getSignature().getName()
            + " product=" + product.getName() + " qty=" + quantity);
    }
}
书中写法（Spring 2.5 时代）
  • 手写 application-context.xml
  • 在 XML 里声明 <aop:aspectj-autoproxy/>
  • 手动把 aspectjweaver.jar 加进 classpath
推荐的现代写法
  • Spring Boot 3.x + spring-boot-starter-aop
  • 切面类打 @Aspect + @Component，交给组件扫描
  • 不需要写任何 XML，也不用手写 @EnableAspectJAutoProxy
pom.xml（关键依赖）
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
🔧 为什么这一个依赖就够了

spring-boot-starter-aop 会同时带来 spring-aop 和 aspectjweaver， 并且 Spring Boot 的自动配置（AopAutoConfiguration）会在检测到它时自动开启 @EnableAspectJAutoProxy 的效果——你只管写 @Aspect 类即可， 这也是普通 Spring（非 Boot）项目里手写 @EnableAspectJAutoProxy 或 XML <aop:aspectj-autoproxy/> 在 Boot 时代基本"消失"的原因。

4. Spring AOP 不够用了怎么办：请出完整版 AspectJ

Spring AOP 只是"AspectJ 切点语法" + "代理"的组合，能力天生有边界：

当你发现自己老是要绕开 self-invocation 限制、或者想拦截一个压根不是 Spring Bean 的普通对象（比如领域模型 Order、Product）时， 就该考虑让 Spring 把这些"非托管对象"也交给 AspectJ 的加载期织入（LTW）处理——书中 9.5 节的 ch09/workspace/Section9.5.2Spring-drivenLTW 示例演示的正是这种"Spring 驱动 LTW"的组合拳： 容器负责装配 Bean，AspectJ 负责在类加载时把切面焊进任意类（包括非 Bean 的领域对象）。

5. 该怎么选：决策指南

🧭 一个简单的判断标准

先用 Spring AOP。日志、鉴权、简单事务这类"只针对 Service 层方法"的需求，Spring AOP + @Aspect 已经足够， 配置简单、无需额外构建步骤。
遇到下面任一情况再换 AspectJ：需要拦截 new 出来的领域对象、需要拦截 static 方法、 需要拦截同一个类内部的方法调用、或者目标对象根本不受 Spring 容器管理。

✏️ 动手练习

运行 ch09/workspace/Section9.1.2Utilizing@Aspect 里的例子，观察 InventoryAuditing 切面输出的审计日志； 然后故意在 InventoryServiceStubImpl 里让 addProduct() 内部调用同一个类的另一个方法， 看看这次调用是否还会打印审计日志——验证一下本章讲的"自调用陷阱"。

小结 & 自测

  • Spring AOP 的底层实现方式是什么？
    运行时生成代理对象（接口用 JDK 动态代理，具体类用字节码子类代理），在代理里插入通知逻辑再转发给真实对象，并不修改原始字节码。
  • 为什么 Bean 内部"自己调自己"的方法不会被增强？
    因为切面只挂在代理对象上，自调用走的是 this 引用，直接命中原始目标对象，根本没有经过代理，所以通知链不会被触发。
  • Spring Boot 项目里为什么很少见到 @EnableAspectJAutoProxy？
    因为引入 spring-boot-starter-aop 后，Spring Boot 的自动配置会自动启用它，不需要手写。
  • 什么信号提示你应该从 Spring AOP 换成完整版 AspectJ？
    需要拦截非 Spring Bean 对象、static 方法、构造函数、字段访问，或者被自调用问题反复困扰时。
