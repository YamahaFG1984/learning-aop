第 6 章

把切面拼在一起

一句话概括本章：前面几章讲了切面能做什么，这一章讲切面自己是怎么“活”的——什么时候创建实例、多个切面谁先谁后、以及一些很少用但要认识的高级特性。

本章你将学到

  • 切面到底是不是普通对象？它的实例什么时候被创建
  • 五种切面关联方式：默认单例、perthis/pertarget、percflow、pertypewithin
  • 当多个切面/多条通知命中同一个连接点时，执行顺序由谁决定
  • privileged 切面：访问私有成员的“特权”，以及它在现代 Java 上的限制

1. 切面也是对象，只是创建方式很特别

你可能已经注意到，前几章的切面里可以写字段、写普通方法，几乎和类一样。没错——切面在运行时也是一个对象， 只不过它的实例化时机不像普通对象那样由 new 决定，而是由 AspectJ 织入器根据“关联策略”自动创建。 这一点很关键：如果你想在切面里存状态（比如一个计数器、一把锁），就必须先搞清楚这个切面到底有几个实例、分别绑定给谁。

💡 类比

普通对象像“自己去银行开户”——你主动 new 一个。切面更像“信用卡自动续期”——银行（织入器）按照你选的套餐 （关联策略：单例 / 每个对象一张 / 每次通话一张……）在后台自动帮你办好，你只管用。

2. 五种关联（association）策略

默认情况下，一个切面在整个程序里只有一个实例（单例），所有匹配的连接点都共享这一份状态。但你可以用下面几种关键字改变这一点：

关联方式含义典型场景
（默认，不写）全局唯一一个切面实例日志、监控这类无状态或全局共享状态的切面
perthis(切点)每个"执行对象（this）"一个切面实例要给每个业务对象维护独立状态，比如每个账户一把锁
pertarget(切点)每个"目标对象（target）"一个切面实例和 perthis 类似，用于代理场景下 this≠target 的情况
percflow(切点)每次进入这段调用链（一次外部调用）一个实例一次事务、一次请求内共享的上下文，如事务管理
pertypewithin(类型模式)每个匹配到的"类"一个切面实例（不是每个对象）按类统计信息，比如给每个 Service 类维护调用计数

书中用一个账户操作的例子展示 pertypewithin——注意它是“每个类”一个实例，不是“每个对象”：

ch06/workspace/Section6.2.4PerTypeAssociation — AssociationDemoAspect.aj
public aspect AssociationDemoAspect pertypewithin(Account+) {
    public AssociationDemoAspect() {
        System.out.println("Creating aspect instance");
    }

    pointcut accountOperationExecution(Account account)
        : (execution(* Account.credit(..)) || execution(* Account.debit(..)))
          && this(account);

    before(Account account) : accountOperationExecution(account) {
        System.out.println("aspect: " + this + "\tobject: " + account);
    }
}
// Account 的每一个子类（包括 Account 本身）都会各自拥有一份 AssociationDemoAspect 实例，
// 而同一个子类的所有对象共用这一份实例

3. 谁先执行：切面优先级（precedence）

当两个切面的通知同时命中同一个连接点（比如“进门”这个动作，既触发安防切面又触发节能切面），谁先执行、谁后执行？ 默认顺序不可依赖，AspectJ 提供 declare precedence 让你显式声明顺序：

ch06/workspace/Section6.3.2ExplicitAspectPrecedence — 三个文件精简展示
public aspect HomeSecurityAspect {
    before() : execution(void Home.exit()) { System.out.println("Engaging"); }
    after()  : execution(void Home.enter()) { System.out.println("Disengaging"); }
}

public aspect SaveEnergyAspect {
    before() : execution(void Home.exit())  { System.out.println("Switching off lights"); }
    after()  : execution(void Home.enter()) { System.out.println("Switching on lights"); }
}

// 显式指定：安防切面永远先于节能切面执行
public aspect HomeSystemCoordinationAspect {
    declare precedence: HomeSecurityAspect, SaveEnergyAspect;
}

同一个切面内部，多条通知命中同一个连接点时，也有明确规则（同类型通知按声明顺序，around 会把 before/after 包在里面）：

ch06/workspace/Section6.3.3OrderingOfAdviceInSingleAspect — InterAdvicePrecedenceAspect.aj
public aspect InterAdvicePrecedenceAspect {
    public pointcut performCall() : call(* Main.perform());

    after() returning : performCall() { System.out.println("<after1/>"); }
    before()          : performCall() { System.out.println("<before1/>"); }
    void around()     : performCall() {
        System.out.println("<around>");
        proceed();
        System.out.println("</around>");
    }
    before()          : performCall() { System.out.println("<before2/>"); }
}
// 实际输出顺序：<around> <before1/> <before2/> ...perform()... <after1/> </around>
// 记忆技巧：around 永远包裹在最外层；同类型的 before/after 按“书写顺序”执行

4. privileged 切面：访问私有成员的“特权”

正常情况下，切面和普通类一样，不能访问其他类的 private 成员。privileged 关键字可以打破这层封装，让切面直接读写目标类的私有字段——书里主要用来做一些调试/测试场景下的“越权”访问。

⚠️ 现代实践建议

在现代代码库里，privileged 切面几乎不推荐使用：它破坏了封装性，让代码的实际行为脱离了类本身的文档和契约， 调试和重构都会变得更难。此外，Java 9+ 的模块系统（JPMS）对跨模块反射访问私有成员做了更严格的限制， 如果目标类在别的模块里，即使用了 privileged，也可能因为模块没有 opens 给你的切面所在模块而在运行时失败。如果只是想在测试里检查私有状态，优先考虑包内可见的测试辅助方法，而不是 privileged 切面。

🔧 小结一下现代取舍

日常业务开发中，90% 的场景用默认单例关联就够了（日志、监控、事务边界通知等都是无状态或用 ThreadLocal/请求上下文管理状态）。perthis/percflow 这类更细粒度的关联， 多在你确实需要“每个对象/每次调用独立状态”且不方便用 ThreadLocal 时才考虑。declare precedence 则建议只要项目里有两个以上切面可能命中同一个连接点，就显式声明一下顺序，不要依赖“凑巧能跑”的默认顺序。

✏️ 动手练习

运行仓库 ch06/workspace/Section6.3.3OrderingOfAdviceInSingleAspect， 对照实际打印的顺序验证上面这段代码的执行顺序；再打开 ch06/workspace/Section6.3.2ExplicitAspectPrecedence， 试着删掉 declare precedence 那一行，看看输出顺序是否还稳定。

小结 & 自测

  • 切面实例是什么时候被创建的？
    不是你手动 new 出来的，而是 AspectJ 织入器根据切面声明的关联策略（默认单例，或 perthis/pertarget/percflow/pertypewithin）自动创建和管理的。
  • perthis() 和 pertarget() 有什么区别？
    perthis() 按“执行对象（this，即调用方法的那个对象在通知里看到的 this）”分配实例；pertarget() 按“目标对象（target，被调用方法所在的对象）”分配。多数情况下 this 和 target 是同一个对象，但在有代理/委托的场景下两者可能不同。
  • 如果两个切面都对同一个方法做了 before 通知，且没有声明 precedence，会发生什么？
    AspectJ 会给出一个确定但不建议依赖的默认顺序（与编译/声明顺序相关），最佳实践是用 declare precedence 显式声明，避免顺序被后续重构意外打乱。
  • 为什么现代项目里不太推荐用 privileged 切面？
    因为它绕开了封装，让代码行为脱离类的公开契约，增加维护难度；同时在 Java 模块系统下，跨模块访问私有成员还可能因为没有显式 opens 而在运行时报错。
