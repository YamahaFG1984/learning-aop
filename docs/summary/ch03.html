CHAPTER 03

理解连接点模型

一句话概括本章：先搞懂 AspectJ 到底能在程序的“哪些时刻”插手做事（连接点），再学会用切点表达式精确挑出你想要的那些时刻。

本章你将学到

  • 连接点（join point）到底是什么，AspectJ 只暴露哪些种类的连接点
  • 新手最容易搞混的一对概念：call（调用处）vs. execution（执行体）
  • 切点（pointcut）的签名语法：通配符 *、..、+ 怎么用
  • 用真实的追踪切面，看懂一段程序执行时到底产生了哪些连接点

1. 连接点：程序执行中的“可插手时刻”

把一次程序运行想象成一部电影，播放过程中有无数个瞬间：某一帧画面、某句台词说出口的一刻、字幕出现的一刻…… 如果你能在这些瞬间里“插播”一段广告，那么每一个可以插播的瞬间，就是一个连接点（join point）。

Java 程序运行时其实有无数个这样的瞬间：调用一个方法、方法体真正执行、给字段赋值、读取字段、抛出异常被 catch 住、类第一次被加载…… 但 AspectJ 并不会把所有瞬间都开放给你，它只精心挑选了一小部分“稳定、有意义”的瞬间对外暴露——这样你写出来的切面才不会因为一次不相关的重构（比如把一行代码拆成两行）就莫名其妙失效。

💡 类比

连接点有点像 PowerPoint 里的“动画触发点”——它不是画面上任意一个像素，而是“某个对象出现”“某次点击”这种被明确定义、可以挂动画的时刻。AspectJ 的连接点也是同理：只在明确定义的程序时刻才能挂上你的逻辑。

2. 最容易踩坑的一对概念：call vs. execution

书里用一个记账系统举例：AccountService 调用 Account.debit()。这里其实藏着两个不同的连接点：

  • call 连接点：发生在调用方那一行代码——“我要调用 debit() 了”。
  • execution 连接点：发生在被调用方——debit() 方法体真正跑起来的那段过程。

用本仓库 ch03 的真实例子来看会更直观：Main.main() 里执行了 new Order().getTotalPrice()。

图 3-1　同一次方法调用，caller 端和 callee 端各有一个连接点——它们不是同一个东西
⚠️ 新手常见错误

如果你想在 Order 类里插入逻辑（比如记录“这个方法被执行了多久”），要用 execution()； 如果你只想在调用方那里做点手脚（比如统计“Main 一共调用了几次这个方法”），才用 call()。 两者织入（weave）的位置完全不同：execution 把逻辑织进 Order 类本身，call 把逻辑织进每一个调用它的地方。

4. 切点：怎么“挑出”想要的连接点

知道了连接点长什么样，下一步就是学会写切点表达式（pointcut）去精确地把它们选出来。 切点表达式的核心，是对 Java 元素“签名”做模式匹配，AspectJ 提供三个通配符：

通配符含义例子
*匹配任意一段名字（不跨包，不含点）*Account 匹配 SavingsAccount
..匹配任意多段（含点）——用在包名表示“所有子包”，用在参数列表表示“任意个数、任意类型参数”com.shop..*、place(..)
+匹配某类型及其所有子类型Order+ 匹配 Order 及其子类

5. 用真实追踪切面看懂输出

仓库里 ch03/workspace/Section3.3JoinPointDemonstrationExample 有一个很好的教学例子：JoinPointTraceAspect 会打印所有发生在它自己之外的连接点。

ajia/tracing/JoinPointTraceAspect.aj（书中原版，传统语法）
public aspect JoinPointTraceAspect {
    private int callDepth;

    pointcut traced() : !within(JoinPointTraceAspect);

    before() : traced() {
        print("Before", thisJoinPoint);
        callDepth++;
    }
    after() : traced() {
        callDepth--;
        print("After", thisJoinPoint);
    }
    // print(...) 用 callDepth 控制缩进，方便肉眼看出调用层级
}

运行 Main（只是 new Order().getTotalPrice()）后，你会看到类似这样的输出（节选）：

  • 必须用 ajc（AspectJ 自带编译器）编译，普通 javac 无法识别
推荐的现代写法
  • 普通 .java 文件 + @Aspect 注解（第 7 章详细讲）
  • Maven 里配 dev.aspectj:aspectj-maven-plugin 自动调用最新 ajc，IDE 兼容性也更好
同样逻辑的现代 @AspectJ 注解写法（预告第 7 章）
@Aspect
public class JoinPointTraceAspect {
    private int callDepth;

    @Before("!within(ajia.tracing.JoinPointTraceAspect)")
    public void before(JoinPoint jp) {
        print("Before", jp);
        callDepth++;
    }

    @After("!within(ajia.tracing.JoinPointTraceAspect)")
    public void after(JoinPoint jp) {
        callDepth--;
        print("After", jp);
    }
}

小结 & 自测

  • 一句话说说什么是连接点？
    程序执行过程中一个被 AspectJ 明确定义、可以插入横切逻辑的时刻，比如方法执行、字段写入、异常处理等——但不是任意语句，比如单条 if 语句就不是连接点。
  • call 连接点和 execution 连接点最本质的区别是什么？
    位置不同：call 发生在“调用方”那一行代码，execution 发生在“被调用方”方法体内部。织入时机也因此不同——只想影响调用方就用 call，想改方法本身的行为就用 execution。
  • execution(* Order+.*(..)) 里的 + 是什么意思？
    表示 Order 及其所有子类型，不只是 Order 自己。
  • 为什么 Spring AOP 只支持 execution() 这一种连接点？
    Spring AOP 用动态代理实现，代理只能拦截“方法调用”这个层面，没有能力深入到字段读写、异常处理块等更细粒度的字节码层面——这些细粒度能力只有原生 AspectJ 的编译期/加载期织入才具备（第 9 章详细对比）。
  • execution(* Account.*(..)) && call(* Account.*(..)) 这个切点能选中什么？
    什么都选不中！因为一个连接点不可能同时既是 execution 又是 call——两者发生在不同位置。用 && 组合不同"种类"的切点，结果永远是空集，这是新手最常踩的坑之一，应改用 ||。
